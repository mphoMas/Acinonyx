## 1. Classification and threat boundary

### 1.1 Interface status key
- **[Existing]**: Currently implemented in `mas.pm.delivery`, `mas.pm.adapters.*`, `mas.pm.coordinator`, or SQLite schema/triggers.
- **[Proposed]**: Designed in the GHA integration contract and scheduled in the phased implementation backlog.
- **[Unsupported]**: Explicitly excluded from the security model.

### 1.2 Threat boundary and database access note
The controls in this matrix govern the supported Python API (`mas.pm.delivery.DeliveryService`, `mas.pm.coordinator.CoordinatorStore`, and `mas.pm.db.PMDatabase`), as well as isolated guest execution. Direct, privileged host SQL manipulation (e.g. an admin executing raw `sqlite3` updates against `mas_pm.db` on the coordinator host) is an administrative action outside the software application boundary. The security model ensures that runners, guest containers, and network clients never possess database credentials or direct host database access.

## 2. Comprehensive acceptance matrix

| Gate / Remedy | Case Study Diagnosis | Concrete Control & Status | Accountable Component | Testable Failure Scenario | Check Method & Expected Outcome |
|---|---|---|---|---|---|
| **G01: Versioned brief & distinct actors** | Incomplete boundary closure; moving target; unassigned or mixed roles. | `DeliveryBrief` model validation requires exact base SHA, policy version, scope list, requirements, checks, and 4 pairwise distinct principals (coordinator, builder, verifier, reviewer). **[Existing]** | `mas.pm.delivery.DeliveryBrief` [Existing] | Attempting to establish a brief with only 3 distinct actors, or where builder == verifier. | Instantiate `DeliveryBrief` with duplicate principals; assert `ValueError` with `"Four distinct assigned principals required"`. |
| **G01 (Workflow): Pinned workflow origin** | Workflow definitions or action versions silently changing. | Workflows trigger on valid events (`pull_request`, `merge_group`, `workflow_dispatch`), use pinned action commit SHAs, and check out trusted oracle from `base_commit_sha`. **[Proposed]** | `gha.workflow` [Proposed] | Workflow runs using unpinned mutable tag or unapproved workflow ref. | Gateway validates `job_workflow_ref`; rejects token if workflow ref does not match approved default branch ref. |
| **G02: Additive positive & adverse checks** | Tests measured weaker properties; lack of negative/falsification checks; superficial passing. | Brief validation requires every requirement to have at least one positive check (`negative=False`) and at least one adverse check (`negative=True`). Critical tasks require non-empty `mechanism`. **[Existing]** | `mas.pm.delivery.DeliveryBrief` [Existing] | Establishing a brief where a requirement lacks an adverse/falsification check. | Call `DeliveryBrief.model_validate()` with a requirement lacking a negative check; assert `ValueError` with `"Each requirement needs positive and adverse-case checks"`. |
| **G02 (Digest): Oracle vs suite digest** | Confusing canonical solve digest with general test trees; candidate modifying tests. | Keep canonical `suite_digest` for solve(payload) contract **[Existing]**. Add separate `oracle_digest` for base-ref harness **[Proposed]**. Candidate test edits evaluated as candidate source, never altering the running oracle **[Proposed]**. | `EvidenceTrust` [Existing] / `gha.runner` [Proposed] | Candidate PR modifies test assertions in `tests/` to manufacture passing tests. | Runner runs tests using `./trusted-oracle` from base ref; candidate test changes do not affect the executing assertions; unauthorized changes outside `brief.scope` trigger scope violation. |
| **G03: Pre-spawn & intent linkage** | Concurrent integration races; untracked or orphaned executions; execution on stale brief. | `require_dispatch()` and `record_dispatch()` link intent to exact task and brief version within SQLite atomic transaction. Intent pre-spawn verifies version matches. **[Existing]** | `mas.pm.delivery` [Existing] / `CoordinatorStore` [Existing] | Dispatching an intent against an issue whose policy version or path whitelist changed after brief establishment. | Mutate `pm_issues.policy_version` and attempt dispatch; assert `DeliveryGateError` with `"Stale delivery brief or pending plan reconciliation"`. |
| **G04: Candidate-bound submission** | Execution success mistaken for process acceptance; candidate substitution. | `DeliveryService.submit()` strictly requires completed run: `run.candidate_commit_sha == submission.candidate_sha`, `run.status == 'EXITED'`, `exit_code == 0`, and task in `AWAITING_SUBMISSION` or `READINESS_RETURNED`. **[Existing]** | `mas.pm.delivery.DeliveryService` [Existing] | Attempting to call `submit()` directly from `READY` phase, or with mismatched candidate SHA. | Call `submit()` while phase is `READY`; assert `DeliveryGateError` with `"Successful execution required before submission"`. Call `submit()` with mismatched `candidate_sha`; assert `DeliveryGateError` with `"Submission is not bound to successful current execution"`. |
| **G04 (Screening): Readiness screening** | Broken candidates sent directly to reviewers, wasting human/senior review capacity. | Builder submits check observations. Any non-passing check or missing check produces `READINESS_RETURNED`. Candidate does NOT enter `IN_REVIEW`. **[Existing]** | `mas.pm.delivery.DeliveryService` [Existing] | Candidate fails 1 of 5 checks; builder submits observations. | Call `submit()` where one observation outcome is `FAILED` or `SKIPPED`; assert returned task phase is `READINESS_RETURNED`, not `IN_REVIEW`. Reviewer receipt admission is refused. |
| **G04 (Lifecycle): Resubmission vs new attempt** | Conflating observation re-reporting for same candidate with new candidate attempt. | Re-submitting corrected observations for the same completed candidate calls `submit()` **[Existing]**. New candidate commit requires `retry_readiness()` transition returning task to `READY` for new attempt **[Proposed]**. | `mas.pm.delivery` [Existing & Proposed] | Calling `require_dispatch()` while task is in `READINESS_RETURNED` without an authorized transition. | Call `require_dispatch()` on task in `READINESS_RETURNED`; assert `DeliveryGateError` with `"Agreed, ready delivery brief required"`. |
| **G05: Justified blocking findings** | Reviewers introducing undisclosed new requirements as defects, or rejecting without reproduction. | `DeliveryService.reject()` requires explicit `Finding` objects citing an existing requirement in the brief, reproduction, impact, and closure paths. **[Existing]** | `mas.pm.delivery.DeliveryService` [Existing] | Reviewer attempts to reject with a finding referencing an unlisted requirement ID. | Call `reject()` with an unlisted `requirement_id`; assert `DeliveryGateError` with `"New requirement must be recorded as scope change, not rejection"`. |
| **G05 (Scope): Explicit scope changes** | Optional improvements or new requirements silently becoming blockers. | New requirements must be submitted via `request_scope_change()`. Coordinator either establishes updated brief (incrementing version) or calls `decline_scope_change()`. **[Existing]** | `mas.pm.delivery.DeliveryService` [Existing] | Attempting to bypass a pending scope change request through ordinary `resume()`. | Call `request_scope_change()` then attempt `resume()`; assert `DeliveryGateError` with `"Resolve pending scope proposal before correction resumes"`. |
| **G06: Related-path closure coverage** | Incomplete fixes closing only the symptom while leaving related paths open. | `Submission` must provide `closures: dict[str, list[str]]` covering all `closure_paths` specified in open findings. **[Existing]** | `mas.pm.delivery.DeliveryService` [Existing] | Builder submits a fix that addresses the finding but omits one of the required related paths from `closures`. | Call `submit()` with incomplete closure paths; assert outcome is `READINESS_RETURNED` with reason `"Incomplete related-path closure"`. |
| **G06 (Recurrence): Recurrence pause** | Repeated patch loops on the same failed invariant without addressing root cause. | If a reviewer rejects a requirement that was previously claimed closed in `closures`, phase becomes `RECURRENCE_PAUSED`. Reassessment required before new dispatch. **[Existing]** | `mas.pm.delivery.DeliveryService` [Existing] | Candidate resubmitted with fix for Req-A; reviewer rejects Req-A again under a new finding ID. | Call `reject()` on a requirement previously claimed closed; assert phase becomes `RECURRENCE_PAUSED` and `recurring=True` in event body. |
| **G06 (Reassessment): Mandatory design plan** | Blind retry of failing work without architectural reconsideration. | In `RECURRENCE_PAUSED`, dispatch is blocked. Only coordinator calling `resume(design_plan=...)` can return task to `READY`. **[Existing]** | `mas.pm.delivery.DeliveryService` [Existing] | Attempting to dispatch a new worker or GHA run while task is in `RECURRENCE_PAUSED`. | Call `require_dispatch()` while task is `RECURRENCE_PAUSED`; assert `DeliveryGateError` with `"Agreed, ready delivery brief required"`. |
| **G07: Builder challenge of findings** | Reviewer errors or misinterpretations forcing unnecessary code rework. | Builder calls `challenge(finding_id, reason)`. Phase becomes `DISPUTED`. Coordinator resolves with `resolve_challenge(upheld=...)`. If overturned, `resume_review()` permits re-review without code retry. **[Existing]** | `mas.pm.delivery.DeliveryService` [Existing] | Attempting to resume review when blockers remain open, or when challenge was upheld. | Call `resume_review()` while an open blocker exists; assert `DeliveryGateError` with `"Unresolved blockers require correction"`. Verify challenge audit record remains in immutable events ledger. |
| **G08: Independent verification receipts** | Self-approval by builders; forged passing labels in database. | `DeliveryService.accept()` validates distinct verification and review IDs using service-owned `EvidenceTrust`. Receipts must match run, candidate, base, policy, suite digest, and roles. **[Existing]** | `mas.pm.delivery` [Existing] / `EvidenceTrust` [Existing] | Attempting to call `accept()` with verification and review receipts signed by the builder, or with mismatched candidate SHA. | Call `accept()` with builder-signed evidence; assert `PermissionError` or `DeliveryGateError` with `"Trusted evidence does not match delivery assignment"`. |
| **G08 (Authority): Premature DONE prevention** | Supported PM transition to DONE before process acceptance. | `require_accepted()` hook in coordinator and PM store blocks transition to DONE unless `pm_delivery_tasks.phase == 'ACCEPTED'` and receipts are verified in same transaction. **[Existing]** | `mas.pm.delivery` [Existing] / `mas.pm.db` [Existing] | Attempting to close an enrolled PM issue via `update_issue(status='DONE')` while task is in `IN_REVIEW`. | Attempt PM issue close; assert `DeliveryGateError` with `"Independent delivery acceptance required before DONE"`. |
| **G09: Append-only immutable ledger** | Evidence erasure; overwriting previous failed attempts; history lost across restarts. | SQLite triggers `pm_delivery_events_no_update`, `pm_delivery_events_no_delete`, `pm_delivery_submissions_no_update`, `pm_delivery_submissions_no_delete` abort mutations. **[Existing]** | `mas.pm.delivery` DDL triggers [Existing] | Direct SQL `UPDATE` or `DELETE` executed against `pm_delivery_submissions` or `pm_delivery_events`. | Execute `UPDATE pm_delivery_submissions SET outcome='IN_REVIEW' WHERE id=1`; assert `sqlite3.IntegrityError` or `sqlite3.OperationalError` with `"Delivery submissions are immutable"`. |
| **G09 (CAS): Competing stale decisions** | Race conditions between concurrent review comments or runner updates. | All state transitions require exact integer `revision` matching `pm_delivery_tasks.revision`. Mismatch fails with `"Stale delivery revision"`. **[Existing]** | `mas.pm.delivery.DeliveryService` [Existing] | Two concurrent operations attempt to submit against revision 3 simultaneously. | First call succeeds and increments revision to 4; second call with revision 3 fails with `DeliveryGateError` with `"Stale delivery revision"`. |
| **G09 (Ledger): Source event idempotency** | Duplicate webhook dispatches, network retries, or runner crashes re-executing paid work. | Server-owned `pm_source_events` records action ID, payload digest, and status before execution. Same digest returns stored outcome; changed digest rejects. **[Proposed]** | Source Registry [Proposed] | Replaying an action with modified payload digest, or re-dispatching an uncertain job automatically. | Replay request with changed digest; assert `IdempotencyConflictError`. Replay uncertain job; assert retry blocked until explicit reconciliation. |
| **G10: Uncertainty & funding holds** | Runner crashes or cancellations releasing budget holds prematurely or retrying uncontained jobs. | Interrupted or cancelled runs record `UNCERTAIN`. Funding holds remain `HELD`. Gate refuses new dispatch until `reconcile_execution()` is called. **[Existing]** | `mas.pm.delivery` [Existing] / `CoordinatorStore` [Existing] | Attempting to establish a new brief or dispatch an issue while a previous intent is in `UNKNOWN_EXECUTION` or reservation is `HELD`. | Call `establish()` or `reconcile_execution()` while reservation is `HELD`; assert `DeliveryGateError` with `"Funding hold remains unresolved"`. |
| **Security: Container boundary isolation** | Container escaping to host files, Docker socket, network, or credentials. | Candidate check execution reuses qualified `ContainerBoundary`: uid 65534, `--read-only`, `--network=none`, `--cap-drop=ALL`, no Docker socket, 128m memory, 0.5 CPU, 64 KiB output limit, recovery journal **[Existing]**. Extended profile (512m, 1.0 CPU, 1 MiB truncation flag) **[Proposed]**. | `mas.pm.adapters.boundary.ContainerBoundary` [Existing] / GHA-06 [Proposed] | Candidate command attempts to access Docker socket or host filesystem. | Container execution probe attempting to access `/var/run/docker.sock`; assert `FileNotFoundError` or permission denied. |
| **Security: Authentication gateway** | Runner holding coordinator database credentials, direct IAM session, or impersonating builder/reviewer. | Authentication Gateway validates GitHub OIDC JWT (issuer, aud, numeric repo_id/owner_id, pinned 40-hex `job_workflow_sha`, RS256, exp/nbf/iat, replay) and maps strictly server-side to ephemeral `witness` role (`delivery:witness_observe`), preventing builder/reviewer/coordinator impersonation. Zero DB or signing keys on runner. See detailed 22-scenario matrix in `GHA_03_GATEWAY_DESIGN_V1.md`. **[Proposed in GHA-03]** | Authentication Gateway [Proposed] | Runner passes expired token, wrong audience, unapproved workflow SHA, or attempts builder impersonation. | Gateway token validation fails; assert HTTP 401/403 with zero state mutation. See test matrix TC-01 to TC-22. |
| **Security: Safe artifact handling** | Malicious zip with path traversal (`../`), symlinks, or oversized files. | Ingestion checks: at most 64 files, total uncompressed size <= 10 MiB, per-file size <= 2 MiB, safe POSIX relative paths only, no symlinks/hardlinks, byte count and SHA-256 validation. Implemented in offline validator **[Existing in GHA-02]**. | `mas.pm.delivery_validator` [Existing] | Submitting an artifact archive containing `../../etc/passwd` or an incomplete byte stream. | Validator rejects archive with `DeliveryValidatorError`; marks observation `UNAVAILABLE` or returns validation failure. |
| **Freshness: PR-head race prevention** | Merging or accepting stale code when PR branch head has advanced. | Gateway checks PR branch head SHA against candidate commit SHA. If PR head has advanced, candidate is marked `CANDIDATE_SUPERSEDED` and rejected. Required acceptance check emits `failure`, not `neutral` **[Proposed]**. | Source Registry [Proposed] | Submitting candidate commit A when PR head has advanced to commit B. | Gateway freshness check fails; assert candidate rejected as `CANDIDATE_SUPERSEDED`. Required Check Run conclusion marked `failure`. |
| **Publication: Trusted check publisher** | Candidate runner modifying or spoofing GitHub Check Run conclusions. | Candidate runner has no Checks write permissions. Privileged publisher service (Antigravity owned, Codex reviewed) updates Check Runs using GitHub App credentials, mapping coordinator states to exact Checks API status/conclusion enums. Required checks never emit neutral or skipped **[Proposed]**. | Trusted Check Publisher (Antigravity owned, Codex reviewed) [Proposed] | Candidate execution attempts to post a Check Run directly using runner token. | GitHub API rejects check run creation with HTTP 403 (token has `contents: read` only). |
| **Metrics: Repeat work measurement** | Repeat work hidden in chat relays and untracked PR revisions. | `DeliveryService.metrics(issue_id)` aggregates counts of returns, formal submissions, rejections, pauses, scope requests, design reassessments, challenges, overturned findings, and acceptances from immutable events. **[Existing]** | `mas.pm.delivery.DeliveryService` [Existing] | Task undergoes 2 readiness returns, 1 rejection with recurrence pause, and 1 acceptance. | Call `DeliveryService.metrics(issue_id)`; assert `readiness_returns == 2`, `recurrence_pauses == 1`, `acceptances == 1`. |
